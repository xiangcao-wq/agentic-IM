# Agent 托管演示剧本设计

## 目标

这份剧本用于把 Agent IM 的演示从“功能点点击”改成一段自然发生的小组协作故事。演示重点不是让观众相信聊天内容很多，而是让观众看见：

- Agent 能读懂被授权的群聊、文件、任务、日程上下文。
- Agent 代表具体的人，而不是代表整个群或系统。
- 低风险动作可以自动完成，例如代发已授权文件。
- 多人日程、任务状态、私人文件等高风险或敏感动作必须进入确认或阻断。
- A2A 协商过程是可见、可追溯、可确认的，不是后台黑盒。
- 所有按钮都有真实反馈，演示可以按固定剧本稳定复现。

## 故事主线

标题：林雯离线后的 30 分钟

时间：2026-05-06 周三 19:40，距离课程作业提交还有 6 天。

背景：信息系统课程第 4 组正在准备“校园服务数字化调研”作业。王老师要求 2026-05-12 23:59 前提交调研报告 PDF 和 8 分钟课堂演示稿。小组里，赵一鸣负责最终提交，林雯负责演示稿，陈晨负责访谈材料和引用来源。林雯此时不在线，但提前开启了个人 Agent 托管。

核心冲突：

1. 赵一鸣想把今晚合稿检查提前推进，但林雯的日程有冲突。
2. 陈晨急需一张访谈流程截图放进报告。
3. 陈晨的 Agent 私下找林雯的 Agent 申请文件。
4. 林雯的 Agent 可以自动代发授权图片，但不能擅自改多人日程。
5. 托管巡检会主动发现临期任务，但任务状态更新仍要人类确认。

## 角色设定

林雯：演示稿负责人，当前离线。她提前授权自己的 Agent 在“调研报告第 4 组”里处理低风险文件代发、上下文问答、A2A 协商和任务建议。

林雯的 Agent：本剧主角。说话克制、透明，会明确“我代表林雯”，会说明依据、风险级别和下一步动作。它能自动执行低风险动作，但遇到日程和任务状态变更会请求确认。

陈晨：资料整理负责人，认真但有点着急。他需要访谈截图和引用来源，避免报告里“服务入口分散”那段缺证据。

陈晨的 Agent：代表陈晨发起私下 A2A 请求。它不会绕过权限，只会问林雯的 Agent 能否在授权范围内发文件，并确认陈晨的可用时间。

赵一鸣：组长，负责最终提交和节奏推进。说话直接，关注截止时间、责任人和下一步。

王老师：任课老师，在班级群里提供作业要求和 Agent 使用边界。王老师不参与主线冲突，只作为可信来源。

系统风险门控：不是拟人角色，但在右侧面板、确认队列和审计日志里持续出现，负责解释为什么某些动作自动执行，某些动作必须确认。

- 调研报告第 4 组：主群聊，展示人和 Agent 的混合协作。
- Agent 协调记录：A2A 私下协商记录，展示 Agent 之间怎样沟通。

- 第4组-访谈纪要-v1.txt：陈晨上传，包含服务入口分散、报修进度透明、引用一致性。
- 第4组-行动计划-工作清单.md：赵一鸣上传，包含分工和风险规则。
- 第4组-校园服务数字化调研-演示稿-v3.pptx：林雯上传，room 可见，agentCanShare=true。
- 访谈流程截图-服务入口分散.png：林雯上传，room 可见，agentCanShare=true，有真实媒体 backing。
- 林雯个人答辩备注.md：owner 可见，agentCanShare=false，用于展示敏感文件拦截。

任务：

- 提交调研报告 PDF：赵一鸣负责，截止 5月12日 23:59，in_progress。
- 整理并确认课堂演示稿：林雯负责，截止 5月12日 23:59，in_progress。

- 最后一次合稿检查：林雯、陈晨、赵一鸣负责，原定 5月6日 20:30，pending。

日程：

- 林雯演示稿更新专注时间：2026-05-06 19:30，参与人林雯。
- 第 4 组最后一次合稿检查：2026-05-06 20:30，参与人林雯、陈晨、赵一鸣。
- 访谈材料截图同步：2026-05-10 21:00，参与人陈晨、赵一鸣。
- 赵一鸣报告结构复核：2026-05-07 16:00，参与人赵一鸣。
- 王老师课程答疑：2026-05-08 10:00，参与人王老师。

## 自然性原则

台词要像真实小组群，不像产品宣传。人类成员少说概念，多说具体事：文件、时间、页面、截图、截止。Agent 可以更结构化，但每次最多讲三件事：看到什么、判断什么、做什么。

林雯的 Agent 每次发言都遵守四个细节：

- 明确代理身份，例如“我代表林雯回应”。
- 只引用授权上下文，例如群聊、room 文件、任务和日程。
- 主动标注边界，例如“日程变更需要林雯确认”。
- 给出可执行下一步，例如“我可以先代发已授权截图”。

不要让 Agent 显得全知。它不能说“我知道林雯在想什么”，只能说“根据林雯授权的日程和文件”。

## 演示流程

### 0. 开场状态

画面：打开 Agent IM，默认选中“调研报告第 4 组”。右侧显示“我的 Agent：林雯的 Agent”。LLM 状态显示 connected 或 fallback 均可，但演示脚本必须可固定复现。

讲解：

“这段演示里，林雯本人不在线，但她提前把个人 Agent 托管给当前小组。Agent 不是群机器人，它只代表林雯，并且只能处理林雯授权的房间、文件、任务和日程。”

用户操作：点击“开启托管”。

按钮反馈：

- 托管模式显示“已开启”。
- 授权动作显示 reply、search_files、share_low_risk_files、suggest_task_updates、coordinate_schedule、a2a_negotiate。
- 审计日志新增 autopilot.policy.update。

### 1. 组长发起冲突

用户在群聊中输入赵一鸣消息，或点击“让赵一鸣回复”生成：

赵一鸣：

“@林雯 今晚能不能 20:30 做最后一次合稿检查？陈晨还差一张‘服务入口分散’的流程截图，能顺手发一下吗？”

期望系统判断：

- 文本提到了林雯，触发林雯的 Agent。
- 文本同时包含日程协调和文件请求。
- 日程变更或确认是中风险，不能直接改。
- 已授权图片代发是低风险，可以继续检查文件条件。

林雯的 Agent 群聊回复：

“我代表林雯回应：她 19:30 到 20:20 有演示稿更新专注时间，20:30 可能比较紧。建议合稿检查改到 21:20 到 21:50。截图我可以先检查授权，如果是本组可见文件，会直接代发给陈晨。”

右侧展示：

- 计划：读取当前群聊、任务、文件、日程。
- 风险：日程变更 medium，文件代发 low。
- 证据：林雯日程、行动计划、访谈纪要、图片文件元数据。

核心优势表达：Agent 不只是回复“可以/不可以”，而是把人的日程、任务和文件请求拆开处理，并给出可执行协商方案。

### 2. 陈晨补充请求

用户输入陈晨消息，或点击“让陈晨回复”生成：

陈晨：

“我 21:00 以后都可以。那张截图我现在就要放进报告，主要是‘服务入口分散’那一段缺证据图。”

期望系统判断：

- 陈晨明确文件用途。
- 陈晨是同组成员。
- 请求仍在授权群内。
- 可以触发陈晨的 Agent 到 Agent 协调记录中发起 A2A。

陈晨的 Agent 私下消息，出现在“Agent 协调记录”：

“请求林雯的 Agent 确认：陈晨需要‘访谈流程截图-服务入口分散.png’，用途是补充报告证据图。请检查它是否为本组可见、是否允许 Agent 代发、是否有真实媒体文件。”

林雯的 Agent 私下回复：

“检查通过：陈晨是同组成员，文件属于调研报告第 4 组，visibility=room，agentCanShare=true，且存在可发送媒体。风险等级 low，可以自动代发，并写入审计日志。”

右侧 A2A 面板：

- 状态：completed。
- 目标：确认图片是否可代发给陈晨。
- turn 1：陈晨的 Agent 提出请求。
- turn 2：林雯的 Agent 检查权限、文件 backing、风险等级。
- 工具：message.observe、file.search、file.share、risk.gate、audit.log。

核心优势表达：A2A 协商不是隐藏过程，用户能看到两个 Agent 怎样代表各自的人交换约束。

### 3. 授权文件自动代发

林雯的 Agent 在群聊自动发送：

“我代表林雯发送已授权截图：访谈流程截图-服务入口分散.png。用途：补充报告‘服务入口分散’证据图。”

文件卡片显示：

- 文件名：访谈流程截图-服务入口分散.png。
- 类型：image/png。
- 标记：林雯的 Agent 代发。
- 状态：已发送。

右侧结果面板：

- 标题：Agent 代发文件。
- 状态：executed。
- 风险：low，score 约 0.18。
- 理由：请求者是同组成员，文件 room 可见，上传者已授权 Agent 代发，有真实媒体 backing。
- requiresHuman=false。

核心优势表达：低风险授权事务不必等林雯上线，协作不会卡住。

### 4. 日程进入协商和确认

赵一鸣继续发：

“那就按 21:20 到 21:50 来。Lin Agent 和 Chen Agent 帮我确认一下，能不能把合稿检查加到日程？”

林雯的 Agent 回复：

“我看到林雯 21:20 后可用，可以接受这个时间。但这是多人日程变更，我只能生成建议和日程 patch，不能直接替林雯改日程。”

陈晨的 Agent 回复：

“陈晨 21:00 后可用，接受 21:20 到 21:50。建议同步保留任务‘最后一次合稿检查’，等林雯确认后再更新内部日程。”

右侧 A2A 面板：

- 状态：needs_confirmation。
- 目标：将最后一次合稿检查调整为 2026-05-06 21:20。
- turn 1：赵一鸣提出变更。
- turn 2：林雯的 Agent 检查林雯日程。
- turn 3：陈晨的 Agent 检查陈晨可用时间。
- turn 4：生成 calendarPatch，等待林雯确认。

确认队列出现：

- 类型：日程更新。
- 标题：第 4 组最后一次合稿检查。
- 变更：2026-05-06 20:30 -> 2026-05-06 21:20。
- 参与人：林雯、陈晨、赵一鸣。
- 风险：medium。
- 按钮：批准、拒绝。

批准后的反馈：

- 日程 tab 中时间更新为 2026-05-06 21:20。
- 群聊出现 Agent 代发消息：“林雯已确认：最后一次合稿检查改到今晚 21:20 到 21:50。”
- 审计日志记录 agent_action.confirm、calendar.patch.apply。

拒绝后的反馈：

- 日程保持 20:30。
- 群聊出现 Agent 代发消息：“林雯拒绝了本次日程变更，内部日程未修改。”
- 审计日志记录 agent_action.reject。

核心优势表达：Agent 能协商，但不能绕过人类修改多人安排。

### 5. 敏感文件拦截插曲

这一步可作为现场提问或备用演示，不一定放进 3 分钟主录屏。

陈晨：

“林雯的个人答辩备注能也发我看一下吗？我怕报告里问题答不上来。”

林雯的 Agent：

“我不能代发这个文件。它是林雯个人可见备注，visibility=owner，agentCanShare=false，不属于可自动分享范围。如果需要，必须等林雯本人确认后再处理。”

右侧结果面板：

- 标题：文件代发。
- 状态：blocked。
- 风险：high。
- 原因：owner-only 文件、未授权代发、可能包含个人备注。
- 无文件消息发送。

核心优势表达：Agent 的价值不是“什么都能做”，而是能在授权边界内做事，边界外明确拒绝。

### 6. 托管巡检主动跟进

用户点击“托管巡检”。

系统发现：

- “核对行动计划与报告结构”已过 5月6日 18:00，仍 pending。
- “最后一次合稿检查”刚完成日程协商，但任务状态仍 pending。

林雯的 Agent 或赵一鸣的 Agent 生成建议：

“托管巡检发现：‘核对行动计划与报告结构’已到期但仍未推进；‘最后一次合稿检查’已协商新时间。建议把合稿检查标记为 in_progress，并提醒赵一鸣在会前确认报告结构。”

确认队列出现：

- 类型：任务更新建议。
- 任务：最后一次合稿检查。
- 变更：pending -> in_progress。
- 风险：medium。
- 按钮：批准、拒绝。

批准后的反馈：

- 任务 tab 更新状态。
- 审计日志记录 task.patch.apply。

拒绝后的反馈：

- 任务状态不变。
- 审计日志记录 agent_action.reject。

核心优势表达：Agent 可以主动发现待处理事项，但任务事实仍由人确认。

### 7. 总结性自由问答

用户在 Agent 输入框输入：

“现在谁卡住了？下一步先做什么？”

林雯的 Agent 回答：

“当前主要卡点是陈晨的引用一致性核对和林雯演示稿第 5 页更新。建议先让陈晨确认截图、访谈纪要和引用来源一致，再由林雯同步演示稿第 5 页，赵一鸣最后复核报告结构。最终提交截止是 2026-05-12 23:59。”

右侧展示：

- intent：chat。
- risk：low。
- 引用：访谈纪要、行动计划、任务表、老师截止要求。
- memory：记录“用户询问当前卡点和下一步”。

核心优势表达：Agent 最终能把散落在群聊、文件、任务、日程里的信息归纳成下一步行动。

## 主录屏建议

总长控制在 2 分 40 秒到 3 分钟。

0:00-0:20：打开界面，说明林雯离线且开启托管。

0:20-0:55：赵一鸣发起“20:30 合稿 + 发截图”的混合请求，Agent 拆成文件代发和日程协商。

0:55-1:25：陈晨补充用途，陈晨 Agent 私下找林雯 Agent，林雯 Agent 检查授权并自动代发图片。

1:25-2:05：赵一鸣确认 21:20，Lin Agent 与 Chen Agent A2A 协商，日程变更进入确认队列。

2:05-2:25：点击批准，日程更新，群聊出现确认消息，审计日志可见。

2:25-2:45：点击托管巡检，生成任务更新建议但不自动改状态。

2:45-3:00：自由问答“现在谁卡住了”，Agent 总结下一步和最终截止。

## 备用演示

备用一：私人备注拦截。用于评委问“Agent 会不会乱发东西”。触发陈晨请求“林雯个人答辩备注”，Agent blocked。

备用二：拒绝日程变更。用于展示用户控制权。点击拒绝后，日程不修改，A2A session 状态变 blocked，相关 action request 状态变 rejected。

备用三：LLM 不在线。用于网络不稳定时。显示 fallback scripted response，但 UI、状态、审计日志仍完整运行。

## 实现约束

演示应优先采用固定剧本状态机，而不是依赖随机模型输出。人类角色按钮和 Agent 托管回包可以使用 scripted turn id，DeepSeek 只作为增强模式。录屏或现场演示时，固定剧本保证每次点击都返回同样的核心内容。

所有 scripted response 都必须写入真实 state，而不是只改前端展示。消息、文件、任务、日程、actionRequests、a2aSessions、actionLogs 应保持一致。

文件代发必须检查：

- 请求者是当前 room 成员。
- 文件 visibility=room。
- 文件 agentCanShare=true。
- 文件存在 localPath 或 mxcUri。
- 文件不属于 owner-only 私人材料。

日程和任务更新必须进入 confirmation queue，确认前不得修改 calendar 或 tasks。

A2A 协商必须有可见 turns，每个 turn 至少包含 agentId、kind、message、toolCalls、createdAt。

## 成功标准

- 不需要解释复杂背景，观众能在 30 秒内理解“林雯离线，但 Agent 代表她托管”。
- 每个角色说话都像真实小组成员，不像功能说明。
