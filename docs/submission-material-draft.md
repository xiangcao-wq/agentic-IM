## 三、模块一：用户洞察与问题定义

### 目标用户

目标用户是以课程小组、学生社团、竞赛团队、轻量项目组为代表的高频协作人群。典型角色包括：

- 组长：负责推进进度、收口材料、催办任务。
- 资料负责人：整理访谈、截图、引用来源和报告附件。
- 演示负责人：维护演示稿版本、同步最新文件。
- 暂时离线成员：希望自己的 Agent 能在授权范围内继续响应低风险请求。

### 用户痛点

1. 协作信息分散在群聊、文件、任务和日程中，成员经常重复问“谁负责”“截止时间是什么”“最新文件在哪”。
2. 传统聊天工具只能展示消息，不能理解任务上下文，也不能把文件、日程和责任人串起来。
3. 现有 AI 助手多数停留在问答层，无法进入真实协作流程；如果直接赋予执行权，又容易越权代发、误改日程、泄露私有内容。
4. 成员离线时，低风险事务会被卡住，比如“把已授权的最新演示稿发给同组成员”；高风险事务又必须保留人工确认，例如多人日程变更。

### 使用场景

本项目的 Demo 设定为“信息系统课程第 4 组完成校园服务数字化调研”。群里存在老师要求、小组分工、访谈纪要、行动计划、演示稿和最终提交截止时间。用户可以直接向林雯的个人 Agent 提问，或让 Agent 在林雯离线时处理授权事务。

核心场景：

- 查询上下文：用户问“谁负责访谈材料？我今天先做什么？”Agent 读取授权群聊、任务和文件后回答。
- 离线代发：组员请求林雯的 Agent 发送最新材料，Agent 检查文件是否 room 可见、是否授权、是否有真实媒体 backing，再决定是否自动代发。
- Agent 协调：组长提出改期，Lin Agent 与 Chen Agent 形成 A2A 协商记录；日程变更被识别为高风险，进入人工确认队列。
- 托管跟进：后台 worker 扫描临近截止任务，生成任务更新建议，但确认前不修改内部任务状态。

## 四、模块二：产品方案设计

### 产品概述

Agent IM 是一个面向团队协作的 AI 原生即时通讯工作台。它不是在聊天界面旁边外挂一个问答机器人，而是让每个用户拥有一个受授权边界约束的个人 Agent。Agent 可以读取自己被授权的房间、文件、任务和日程，基于真实上下文回答问题；对文件代发、任务更新、日程协调等动作，则通过工具白名单、风险评估和人工确认机制执行。

当前项目已经实现了可运行 Demo：

- React/Vite 前端工作台，包含群聊、文件、任务、日程、成员和 Agent 工作区。
- 本地 API 持久化到 `data/agent-im-db.json`，聊天、Agent 运行、审计日志和确认队列不依赖前端假状态。
- 可选 Matrix/Synapse 模式，用真实房间、事件和媒体上传下载承载 IM 数据。
- DeepSeek 模型路由：人类 AI 演员默认走 Flash，个人 Agent 默认走 Pro + Thinking。
- Agent 工具体系：上下文问答、群聊总结、截止时间检索、文件搜索、文件代发、Web 搜索、Agent 协调、任务更新建议。

### 核心功能

1. 授权上下文问答
   Agent 只读取被授权房间中的消息、任务、文件元数据和文件文本片段。回答会带有来源引用和运行日志，避免凭空编造内部事实。

2. 文件搜索与离线代发
   Agent 可查找授权文件。只有满足 `room` 可见、`agentCanShare=true`、存在 `localPath` 或 `mxcUri` 的文件，才允许低风险自动代发；个人备注和未授权文件不能被代发。

3. A2A Agent 协调
   当用户提出跨成员协作请求时，个人 Agent 可以生成 A2A 协商记录，说明双方 Agent 的观察、提案、响应和工具结果。

4. 风险门控与确认队列
   只读问答和低风险授权文件代发可以直接执行；日程变更、任务状态变更、多人协调等中高风险动作必须进入确认队列，用户批准后才写入状态。

5. 托管模式自动跟进
   用户可以开启 Agent 托管策略。后台 worker 会扫描待处理任务和消息，自动生成跟进建议或 A2A 会话，但仍遵守风险门控。

6. 审计日志与记忆
   每次 Agent 运行都会记录工具调用、风险等级、上下文来源和结果。Agent 还会写入结构化记忆，用于后续低成本复用。

### 交互流程

主流程 1：上下文问答

1. 用户在 Agent 输入框问“谁负责访谈材料？我今天先做什么？”
2. 系统校验 Agent 是否有权读取当前 room。
3. 后端构建授权上下文，包括消息、任务、文件、成员和相关记忆。
4. LLM 判断 intent 为 `chat`，调用 `chat.answer`。
5. Agent 回答陈晨负责访谈材料，并建议优先处理访谈材料/行动计划。
6. 系统写入 Agent 记忆和审计日志。

主流程 2：离线代发

1. 陈晨在群里请求林雯的 Agent 发送最新材料。
2. Lin Agent 检索授权文件库，匹配最新文件。
3. Agent 检查文件权限、可见性、真实媒体 backing 和目标用户关系。
4. 若低风险，发送带有“林雯的 Agent 代发”标识的文件消息。
5. 若缺少真实媒体或权限不足，则阻断或进入确认队列。

主流程 3：Agent 协调日程

1. 赵一鸣要求将合稿检查改到周三 23:00。
2. Lin Agent 与 Chen Agent 生成 A2A 协商记录。
3. 系统识别日程变更影响多人，风险等级为中/高。
4. Agent 只生成 calendar patch 和建议，不直接修改日程。
5. 用户在确认队列中批准或拒绝。

### 创新与差异化

- 从“聊天机器人”升级为“可审计的个人 Agent 协作层”：Agent 可以理解上下文，也能调用工具，但所有写操作都有边界。
- Agent 代表个人，而不是代表整个群：每个 Agent 只处理 owner 授权的房间和工具。
- A2A 协商是产品界面中的一等对象：不是隐藏的后台调用，而是可以被用户查看、确认和追责。
- 风险分级决定执行方式：低风险自动化提高效率，中高风险保留人类决策。
- Demo 接近真实系统：有持久化状态、真实 API、可选 Matrix 事件、媒体文件、审计日志、浏览器烟测和录屏脚本。

## 五、模块三：AI 原生能力说明

### AI 核心能力

1. 大模型意图识别与规划
   Agent 根据用户自然语言判断是问答、总结、截止日期检索、文件搜索、文件代发、日程协调、任务更新还是 Web 搜索。

2. 多模态/文件上下文利用
   当前实现支持文件元数据和文本片段索引，Demo 中包含 TXT、Markdown、PDF/PNG 等演示资产；说明文档中可以表达为“当前已实现文件文本和元数据理解，视觉图片内容理解是后续扩展方向”。

3. Agent 工具调用
   工具包括 `chat.answer`、`room.summarize`、`deadline.answer`、`file.search`、`file.share`、`web.search`、`agent.coordinate`、`task.suggest_update`。

4. A2A 多 Agent 协作
   个人 Agent 之间可以围绕文件代发、日程变更、任务跟进形成协商会话，并把结论沉淀为确认请求。

5. 记忆与审计
   Agent 把总结、问答、文件处理和协调结果写入记忆；每次动作同步记录来源、工具调用、风险理由和状态。

6. 风险门控
   系统把动作分为只读、低风险写操作和中高风险写操作。只读动作直接回答；低风险授权文件可自动代发；日程/任务修改必须确认。

### AI 如何解决痛点

- 对“信息散落”的痛点：Agent 自动从群聊、任务、文件和记忆中提取上下文，回答负责人、截止时间、最新文件等问题。
- 对“离线协作卡顿”的痛点：成员离线时，个人 Agent 可在授权边界内处理低风险文件代发。
- 对“AI 越权风险”的痛点：所有写操作经过工具白名单、权限检查、风险评估和确认队列。
- 对“多人沟通成本高”的痛点：A2A 协调把跨成员沟通变成可追踪的协商记录。

### AI 技术方案

- 前端：React + Vite，展示 IM、文件、任务、日程、Agent 工作台、A2A 会话和确认队列。
- 后端：Node/TypeScript API，统一处理消息、Agent 运行、文件、状态持久化、事件流和审计日志。
- 状态层：当前使用 JSON StateStore，已抽象为可迁移 SQLite/Postgres 的接口。
- IM 层：可选 Matrix Synapse，承载真实房间、消息事件和媒体上传下载。
- LLM 层：DeepSeek Chat Completions 兼容接口；人类 AI 演员和个人 Agent 分模型路由。
- 工具层：白名单工具按 intent 映射，写操作要求风险门控。
- 可靠性：有单元测试、集成测试、浏览器 smoke 和自动录屏脚本。

## 六、模块四：加分项

### 落地可行性

技术实现路径清晰：当前 demo 已可本地运行，核心状态通过 API 持久化；Matrix 模式可以接入真实 IM 事件；StateStore 已经为数据库迁移留出接口。后续产品化只需要补充登录、组织权限、云端数据库、生产级部署和外部日历/网盘连接。

开发资源评估：

- MVP：1-2 名前端/全栈开发可在现有基础上完成在线体验版。
- 产品化：需要补充账号权限、数据库、对象存储、消息推送、审计后台和安全评估。
- 可扩展方向：企业微信/飞书/Slack 接入、外部日历同步、长周期项目托管、图片/文档视觉理解。

### 商业化思考

目标市场可以从学生团队和轻量项目组切入，逐步扩展到教育协作、科研小组、创业团队和企业内部项目协作。

潜在模式：

- Freemium：基础群聊问答免费，高级 Agent 托管、A2A 协调、更多文件索引额度收费。
- 团队订阅：按团队成员数或 Agent 数收费。
- 教育版：面向课程项目、实验室和竞赛队伍提供低价套餐。
- 企业版：强化权限、审计、SSO、私有化部署和内部知识库接入。

竞争优势：

- 相比普通 IM：Agent 能理解协作上下文并推动流程。
- 相比普通 AI 助手：有明确授权边界、工具执行、确认队列和审计日志。
- 相比项目管理工具：保留群聊自然协作方式，不强迫用户迁移到复杂流程系统。

## 九、Demo 链接上线建议

初赛最稳妥的在线体验策略：

- 前端和 API 部署在同一个服务上，避免跨域和 API 地址配置问题。
- 使用 `npm run demo:prepare` 生成的种子状态，打开页面即进入可演示场景。
- 初赛在线版可先不启用 Matrix 容器，使用本地持久化和媒体 fallback；录屏中可说明 Matrix/Synapse 是可选真实 IM 通道。

- 若部署环境不支持文件写入，应把 JSON StateStore 换成 SQLite/Postgres 或启动时复制 seed 到可写目录。
